# 4 月细化开发计划表

## 一、4 月总目标

4 月要完成 4 条主线：

1. 完成技术部全功能闭环  
   技术部长 + 产品岗 + 开发岗 + 检测岗 + 运维岗全部可跑通

2. 完成可视检索向量知识库  
   文档可导入、可检索、可追溯来源、可前端查看

3. 完成对话框架升级  
   支持连续对话、任务确认、需求澄清、完成后下一步确认

4. 完成语音能力基础版  
   支持语音输入、语音输出、文本流式输出，语音先做“可用版”

---

## 二、执行原则

为了控制风险，4 月采用下面策略：

- 先做“可跑通闭环”，再做“高级体验”
- 先做“文本流式 + 完整语音播报”，再做“严格同步语音流”
- 先做“知识库检索可视化基础版”，再做复杂图谱/分析功能
- 技术部四岗先完成“结构化输出 + 状态流转 + RAG 接入”，暂不追求全部真实工具深集成

---

## 三、4 月按周细化排期

## 第 1 周：4 月 1 日 - 4 月 6 日
### 目标
完成技术部和对话框架的底层结构重构，为后续功能铺路。

### 任务项
1. 技术部状态结构补全
- 梳理技术部主状态字段
- 增加 `任务阶段`、`需求确认状态`、`当前执行岗`、`子任务结果`
- 区分 `用户原始需求`、`最近一次补充需求`、`当前确认需求`

2. 技术部执行链路统一
- 技术部长内部流程统一为：
  `需求分析 -> 子计划生成 -> 分发执行 -> 检测回流 -> 运维收尾`
- 明确 4 个子智能体统一输入输出格式
- 明确失败回流规则

3. 对话框架升级 V1
- 支持连续多轮对话上下文
- 增加“需求不明确时主动澄清”节点
- 增加“任务完成后是否继续下一步”节点
- 增加当前会话任务状态标记

4. 前端会话状态同步
- 会话中显示当前任务阶段
- 可区分“等待确认 / 执行中 / 已完成 / 等待下一步”
- 对接后端状态字段

### 本周交付物
- 技术部状态模型文档
- 对话状态机说明
- 技术部执行链路图
- 前后端状态字段定义表

### 验收标准
- 用户发起技术任务时，系统可以判断需求是否明确
- 若不明确，系统会追问，而不是直接生成结果
- 会话状态不会乱，支持连续多轮

### 风险控制
- 本周不做语音
- 本周不做复杂知识库展示
- 只做底层结构和状态统一

---

## 第 2 周：4 月 7 日 - 4 月 13 日
### 目标
完成技术部 4 个智能体的基础功能，实现完整闭环。

### 任务项
1. 产品岗智能体
- PRD 生成
- 产品方案输出
- UI/UE 页面说明输出
- 内部完整版 / 外部脱敏版区分
- 文档版本号字段

2. 开发岗智能体
- 基于 PRD 生成 Python / 前端 / 后端 / Linux 脚本
- 输出接口文档说明
- 输出代码说明
- 支持按需求选择开发方向

3. 检测岗智能体
- 四维检测框架接入：
  - 代码安全性
  - 代码规范性
  - 功能完整性
  - 兼容性
- 输出检测报告
- 输出漏洞清单
- 输出修复
- 不通过时返回开发岗

4. 运维部署智能体
- 输出部署报告
- 输出运行状态报告
- 输出告警通知
- 输出多节点部署说明

5. 技术部长编排优化
- 根据需求动态决定是否必须经过产品岗
- 支持“只写代码”“跳过测试”“只输出方案”之类分支
- 技术部长总结输出格式统一

### 本周交付物
- 技术部 4 岗可运行版本
- 技术部长动态编排版本
- 技术部端到端演示链路

### 验收标准
- 从需求输入到技术部最终结果可全流程跑通
- 检测失败可回流开发岗
- 前端能看到产品岗、开发岗、检测岗、运维岗输出

### 风险控制
- 子智能体先以 LLM 编排和结构化输出为主
- 暂不做真实 IDE / Android Studio / 服务器深集成

- 检测岗引用企业代码标准/历史缺陷

### 风险控制
- 本周只做“检索可视化”

## 第 4 周：4 月 21 日 - 4 月 27 日
### 目标
重点优化对话体验，并接入语音能力基础版。

### 任务项
1. 连续对话升级
- 支持任务跟进型对话
- 支持中途补充需求
- 支持阶段性确认
- 支持完成后询问“是否继续下一步”

2. 需求确认机制
- 技术类任务缺参数时主动问
- 明确“必须确认项”
- 用户回复后可继续原任务而非重新开始

3. 语音输入
- 前端录音入口
- 音频上传
- 后端 ASR 识别
- 识别文本进入现有会话链路

4. 语音输出
- 文本生成后转语音
- 支持整段播报
- 前端播放控件
- 显示当前播报状态

5. 流式展示优化
- 文本保持流式输出
- 语音先实现“文本完成后播报”
- 预留后续升级“边生成边语音播报”的接口

### 本周交付物
- 连续对话 V2
- 需求确认链路
- 语音输入输出基础版
- 文本流式 + 语音播报联动

### 验收标准
- 用户可语音提问
- 系统可返回文本并播报语音
- 对于模糊需求，系统会确认后再执行
- 完成任务后会问用户是否继续下一步

### 风险控制
- 语音先做“可用版”，不追求超低延迟
- 严格同步流式语音播报放到后续迭代

## 七、验收场景

 4 月底至少用这 4 个场景验收：

1. 技术需求模糊场景
- “帮我做一个分类系统”
- 系统主动追问需求
- 最终完成技术部闭环

2. 技术需求明确场景
- “帮我做一个 Python 分类 API，并输出部署方案”
- 技术部长直接安排各岗执行

3. 知识库支撑场景
- 技术部输出内容中可引用企业规范或行业标准
- 前端可看到检索来源

4. 语音对话场景
- 用户语音输入需求
- 系统文本流式返回
- 最终播报语音结果
- 完成后询问是否继续下一步
